# Realtime — live push

_Auto-generated by `gc build`._

Lists on screen refresh themselves when their table changes. A separate
OpenSwoole process (the **sidecar**) holds the WebSockets; Apache and PHP-FPM
serve every request exactly as before and keep working whether the sidecar is
up or down.

## Turning it on

```bash
gc rt <project> status     # port, pid, socket, live client count
gc rt <project> start
```

Needs `GC_RT_ENABLED="1"` in the project-root `.env` (**not** `.admin/.env`)
and a WebSocket tunnel in the vhost:

```apache
ProxyPass        /<project>/.admin/rt/ws  ws://127.0.0.1:<port>/  upgrade=websocket
ProxyPassReverse /<project>/.admin/rt/ws  ws://127.0.0.1:<port>/
```

## The rule that governs everything here

**The socket carries table names, never row data.** A frame is
`{op:"change", t:"<db_table>", g:"<generation>"}` and nothing more. The client
reacts by re-fetching through the normal API, where RBAC, the ACL and
`id_tenant` scoping apply exactly as on a manual reload.

That is why the sidecar needs no authorization logic: it knows nothing worth
leaking. **Any change that puts record contents on the socket bypasses every
authorization check in this application.** Do not do it.

## Custom client code

Put it in `public/js/project.js` — loaded last, never overwritten by
`--sync-template` (the JS counterpart of `public/css/project.scss`).

```js
gcRealtime.on('invoice', function (e) {
    // e.table = DB table name, e.gen = generation token.
    // Fetch anything you need through the normal API.
});
```

Subscribe by **DB table name** (`invoice`, `api_rbac`) — not the model
PhpName. Registering a listener also subscribes to that table even when no
list for it is on screen. `document.addEventListener("gc:realtime-change", …)`
receives the same events.

## Custom server code

Send your own change signal from anywhere in the app (a Domain, a wrapper):

```php
\ApiGoat\Realtime\Signal::emit('invoice');   // no-op unless GC_RT_ENABLED=1
```

Every emitted ORM save/delete already does this, so you only need it for
changes the ORM does not make (a raw SQL update, an external sync).

## Custom sidecar code (advanced, opt-in)

Define `App\Domains\RealtimeHandler` and the sidecar will call whichever of
these it finds: `onStart`, `onOpen`, `allowSubscribe`, `onMessage`,
`allowPush`, `onClose`. Signatures are documented on
`ApiGoat\Realtime\Hooks`.

**This code runs in a single long-lived event loop, not in a request.**

- Never block — no queries, no HTTP, no `sleep()`. A 200ms call stalls *every*
  connected client for 200ms.
- Never accumulate — the process runs for days; a growing static array is a leak.
- Never push row data (see the rule above).
- There is no `$_SESSION` and no request. The only identity is the verified
  ticket claims: `['u' => authy id, 'tn' => tenant token]`.

A hook that throws is caught and logged; one that throws repeatedly is disabled
for the life of the process. Restart with `gc rt <project> restart` after fixing
it. Log: `.admin/tmp/rt.log`.
