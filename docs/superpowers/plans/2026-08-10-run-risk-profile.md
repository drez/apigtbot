# Per-Run Risk Profile (NoLoss → Max) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `profile` dropdown on a grid run (NoLoss/Cautious/Balanced/Aggressive/Max) that continuously derives the run's risk caps from its budget slice and instructs the hourly refit routine's posture.

**Architecture:** Spec: `docs/superpowers/specs/2026-08-10-run-risk-profile-design.md` (Approach A). A new enum column on `grid_run` + one policy class (`ProfilePolicy`) that stamps the *effective* cap columns (`daily_loss_limit_quote`, `max_unrealized_loss_quote`, `max_position_quote`, `max_order_quote`, `breakout_policy`) from `profile × current slice`. Stamping happens daemon-side each tick and service-side on save, so every existing consumer keeps reading the columns it reads today. NoLoss additionally refuses every loss-realizing path (three layers, BudgetGuard convention). The routine prompt gains a PROFILE POSTURE block.

**Tech Stack:** PHP 8.4, Propel 1 ORM (GoatCheese), bcmath (string decimals), PHPUnit (`.admin/vendor/bin/phpunit`, bootstrap pattern from `tests/Custom/Bot/BudgetGuardTest.php`).

## Global Constraints

- All money math via bcmath on strings, scale 8 (daemon convention).
- Profile enum values exactly: `NoLoss, Cautious, Balanced, Aggressive, Max`; default `Balanced`.
- Cap ratios of slice (spec §2): NoLoss 2%/disabled; Cautious 3%/10%; Balanced 6%/15%; Aggressive 10%/25%; Max 15%/35%; all profiles `max_position = 1.0×slice`, `max_order = 0.30×slice`; breakout `Flatten` only for Aggressive/Max, else `HaltAndHold`.
- NoLoss must never realize a loss: kill-tool refusal + daemon Flatten-command refusal + stamped HaltAndHold (spec §3).
- Working dir for builds/tests: `/path/to/apigtbot/.admin`; build with `../gc build` (non-TTY defaults are safe); deploy is Task 7 only.
- Commit after every task; message style `feat(bot): …` / `docs(routine): …` matching `git log`.

```php
<?php

namespace App\Domains\Bot;

use App\GridRun;

/**
 * Single source of the per-profile risk numbers (spec:
 * docs/superpowers/specs/2026-08-10-run-risk-profile-design.md). The profile
 * is a LIVE policy: caps are ratios of the run's CURRENT budget slice and are
 * stamped onto the grid_run row (daemon each tick, service wrapper on save)
 * so every existing consumer keeps reading the same columns. NoLoss's
 * daily-loss cap only catches fee/slippage dust — nothing in a NoLoss run may
 * realize a loss on purpose (allowsRealizedLoss gates every such path).
 */
final class ProfilePolicy
{
    private const SCALE = 8;

    public const PROFILES = ['NoLoss', 'Cautious', 'Balanced', 'Aggressive', 'Max'];

    /** profile => [daily-loss ratio, unrealized-stop ratio|null, breakout policy] */
    private const RULES = [
        'NoLoss'     => ['0.02', null,   'HaltAndHold'],
        'Cautious'   => ['0.03', '0.10', 'HaltAndHold'],
        'Balanced'   => ['0.06', '0.15', 'HaltAndHold'],
        'Aggressive' => ['0.10', '0.25', 'Flatten'],
        'Max'        => ['0.15', '0.35', 'Flatten'],
    ];

    private const MAX_POSITION_RATIO = '1.00';
    private const MAX_ORDER_RATIO = '0.30';

    /** @return array{DailyLossLimitQuote:string, MaxUnrealizedLossQuote:?string, MaxPositionQuote:string, MaxOrderQuote:string, BreakoutPolicy:string} */
    public static function caps(string $profile, string $sliceQuote): array
    {
        if (!isset(self::RULES[$profile])) {
            throw new \InvalidArgumentException("unknown risk profile: $profile");
        }
        [$daily, $unrealized, $breakout] = self::RULES[$profile];
        return [
            'DailyLossLimitQuote' => bcmul($sliceQuote, $daily, self::SCALE),
            'MaxUnrealizedLossQuote' => $unrealized === null ? null : bcmul($sliceQuote, $unrealized, self::SCALE),
            'MaxPositionQuote' => bcmul($sliceQuote, self::MAX_POSITION_RATIO, self::SCALE),
            'MaxOrderQuote' => bcmul($sliceQuote, self::MAX_ORDER_RATIO, self::SCALE),
            'BreakoutPolicy' => $breakout,
        ];
    }

    /** Only NoLoss forbids realizing losses (flatten/selloff/breakout-Flatten). */
    public static function allowsRealizedLoss(string $profile): bool
    {
        return $profile !== 'NoLoss';
    }

    /** Stamp derived caps onto the row. Returns true when a value changed. Does NOT save. */
    public static function apply(GridRun $run): bool
    {
        $profile = (string) ($run->getProfile() ?: 'Balanced');
        $caps = self::caps($profile, (string) $run->getBudgetQuote());
        $changed = false;
        foreach ($caps as $phpName => $value) {
            $current = $run->getByName($phpName);
            $same = ($value === null && $current === null)
                || ($value !== null && $current !== null && !is_numeric($value)
                    ? (string) $current === (string) $value
                    : ($value !== null && $current !== null && is_numeric($value)
                        ? bccomp((string) $current, $value, self::SCALE) === 0
                        : false));
            if (!$same) {
                $run->setByName($phpName, $value);
                $changed = true;
            }
        }
        return $changed;
    }
}
```

Note for the implementer: the `$same` expression above is intentionally spelled out; if Propel's `getByName` returns floats for decimals, normalize with `(string)` before `bccomp`. Keep the comparison logic readable — refactor into a small private `sameValue(?string $a, ?string $b, bool $numeric)` helper if the inline ternary fights you; behavior (null-safe compare, bccomp for numerics, string compare for BreakoutPolicy) is what the test pins.
